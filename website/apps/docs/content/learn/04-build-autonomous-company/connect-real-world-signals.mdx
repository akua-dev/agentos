## Ingest first; decide from durable evidence

Reality must reach the company: support messages, provider issues, CI, production alerts and
business signals. Durable ingestion is only the beginning. An authorized reconciliation Agent
decides whether the evidence maps to existing intent, deserves new accepted work or requires no
action.

```text
signal → durable evidence → bounded claim → reconciliation → Task or no-op
```

Provider delivery IDs make retries idempotent. A short claim lets one Mate reason without holding a
database transaction; expiry makes abandoned work recoverable.

## Three deliveries, one outcome

A support provider emits three deliveries for the same customer defect. The integration ingests
the complete provider evidence. The support Second Mate claims the batch and finds an existing
checkout Task already covers the outcome.

It completes reconciliation without creating another Task. The provider remains the customer
conversation authority; PostgreSQL owns the Fleet ownership decision.

<Callout title="Possible extension">
Argo Events could receive webhooks and Argo Workflows could run deterministic preprocessing or
human approval gates. Those are integrations, not shipped AgentOS components; they must preserve
the same durable reconciliation and authority boundary.
</Callout>
