## Prove the claim in its authority

As an outcome spans more tools and more time, the chance of interruption, stale assumptions and
partial success rises. Durable work needs checkpoints that another session can inspect and
completion evidence that an independent reviewer can verify.

Evidence is tied to the authority that owns the claim:

| Claim | Useful evidence |
| --- | --- |
| source changed | Git diff and commit |
| checks passed | exact command, exit status and useful output |
| review requested | provider review URL |
| workload recovered | identity, PVC, session and preserved-work observations |
| human approved | exact durable decision |

An ever-growing transcript may explain why the Agent acted. Native artifacts prove what became
true.

## A short, reviewable result

The onboarding Agent can finish with:

```text
commit: 7f4c… add server-side address validation
checks: bun test onboarding (passed, 42 tests)
review: provider-native review artifact URL recorded in the delivery report
remaining risk: existing clients may rely on undocumented whitespace normalization
authority used: branch push + review creation; no merge
```

The report is short because the evidence is durable. If the test failed, preserving its output and
the branch would be more truthful than marking the outcome complete.

One durable Agent can now own work across time. The next problem is organizational: several Agents
still need responsibility, hierarchy and shared truth.
