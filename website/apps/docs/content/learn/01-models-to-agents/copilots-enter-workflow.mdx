## Better context, closer to the work

A copilot can retrieve repository files, apply standing instructions, inspect an issue and suggest
a patch inside the editor. The model sees better context and the human spends less effort moving
information between systems.

Three additions are common:

- **instructions** shape recurring behavior;
- **retrieval** grounds output in relevant current material;
- **integrations** expose external systems.

None makes copied context authoritative. Git owns source, the issue provider owns the issue and a
current test run owns its observed result.

## A suggestion still needs an owner

The copilot retrieves an onboarding handler and proposes server-side validation. That is far better
than a context-free answer, but the human still chooses the file, accepts edits, runs checks,
interprets failure and decides when the change is ready.

The unanswered questions are organizational: Is this the real cause? Which workflow applies? May
the system edit, commit or open a review? What evidence closes the work?

Until those decisions are delegated, the copilot is an excellent pair—not an accountable worker.
