## Action creates consequences

Tools turn a proposed action into a request against an external system. The harness describes
available operations, the model selects one with arguments, and the tool returns an observation
that can influence the next inference.

```text
reason → call tool → external consequence → observe → reason again
```

This is where a generated choice can change reality. Reading a file is modest; sending mail,
spending money, changing infrastructure or merging code is not. Tool availability therefore needs
sandboxing, native permission and organizational authority.

The result is evidence only for the system that produced it. A provider may return an issue while
Git proves that the referenced commit does not exist.

## Inspect, change, verify

The system reads an onboarding issue through the provider, then inspects the handler and tests
through repository tools. It can compare human intent with current source without asking you to
paste either.

Editing the handler creates a consequence. If that write was not authorized, intelligence does not
excuse it. If the edit succeeds but no test runs, the observation is incomplete.

A safe action loop asks:

1. Is this tool allowed in the current sandbox?
2. Is this Agent authorized for the consequence?
3. Which native source proves the result?
4. What observation should change the next plan?
