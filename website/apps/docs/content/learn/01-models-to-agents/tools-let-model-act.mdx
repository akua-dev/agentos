## The mental model

Tools turn a proposed action into a request against an external system. The harness describes
available operations, the model selects one with arguments, and the tool returns an observation
that can influence the next inference.

```text
reason → call tool → external consequence → observe → reason again
```

This is the first layer where a generated choice can change reality. Reading a file is a modest
consequence; sending mail, spending money, changing infrastructure or merging code is much larger.
Tool availability therefore needs sandboxing, native permission and organizational authority.

The tool result is evidence, not automatically truth about everything. A provider call can return
an issue while Git shows the named commit does not exist. The loop must respect the authority of
each system.

## Worked example: inspect the issue

The system calls a provider tool to read the onboarding issue, then uses repository tools to inspect
the handler and tests. It can now compare human intent with current source instead of asking you to
paste both.

If it calls a write tool to edit the handler, an external consequence occurs. If the write was
never authorized, intelligence does not excuse the boundary violation. If the edit succeeds but no
test runs, the observation is incomplete.

A safe action loop asks:

1. Is this tool allowed in the current sandbox?
2. Is this Agent authorized for the consequence?
3. Which native source proves the result?
4. What observation should change the next plan?

## What changes at this layer?

- Generated choices can affect external systems.
- Observations can feed a multi-step loop.
- Permission and authority become product requirements.
- A tool call still does not create a durable owner.
