## The mental model

An Agent accepts a bounded outcome and carries it through a loop:

```text
outcome
  → reason about the next useful step
  → act with permitted tools
  → observe the actual result
  → adjust until complete, blocked or escalated
  → return evidence
```

The delegation threshold is responsibility, not a particular library. The human no longer chooses
every next command. The Agent chooses within a defined scope and knows which consequences require
escalation.

A good outcome says what should become true, what evidence closes it and what authority is absent.
It does not encode a brittle workflow graph for every possible observation.

## Worked example: own onboarding validation

Delegate:

> Ship server-side onboarding address validation through this repository’s existing pull-request
> workflow. Preserve current API compatibility, run the required checks and return the review
> artifact. Do not merge.

The Agent inspects project instructions, confirms the cause, edits in an isolated branch, runs
tests, responds to failures and creates the selected review artifact. If a schema migration becomes
necessary, it stops at that newly consequential boundary rather than silently broadening scope.

The outcome can end in three truthful states:

- **complete**, with commit, checks and review artifact;
- **blocked**, with the exact missing capability or decision;
- **failed**, with preserved work and evidence.

“Still working” is not evidence, and “done” without the selected artifact is not completion.

## What changes at this layer?

- The system, not the human, chooses routine next steps.
- One bounded result becomes the unit of delegation.
- Evidence and escalation define truthful closure.
- Session durability now matters because the outcome outlives one inference.
