## The delegation threshold

An Agent accepts a bounded outcome and carries it through a loop:

```text
outcome
  → reason about the next useful step
  → act with permitted tools
  → observe the actual result
  → adjust until complete, blocked or escalated
  → return evidence
```

The threshold is responsibility, not a library. The human no longer chooses every command. The
Agent chooses routine next steps within a defined scope and escalates consequences it does not own.

A good outcome says what should become true, what evidence closes it and what authority is absent.
It does not pre-script every observation.

## One bounded result

Delegate:

> Ship server-side onboarding address validation through this repository’s existing pull-request
> workflow. Preserve current API compatibility, run the required checks and return the review
> artifact. Do not merge.

The Agent inspects instructions, confirms the cause, edits in an isolated branch, runs checks and
creates the selected review artifact. If a schema migration becomes necessary, it stops at that
newly consequential boundary rather than expanding scope.

The outcome can end in three truthful states:

- **complete**, with commit, checks and review artifact;
- **blocked**, with the exact missing capability or decision;
- **failed**, with preserved work and evidence.

“Still working” is not evidence. “Done” without the selected artifact is not completion.
