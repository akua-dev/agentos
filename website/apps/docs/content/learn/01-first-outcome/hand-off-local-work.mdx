## Recognize the moment

You do not have to begin every outcome inside the Fleet. A local coding Agent can be the fastest
place to explore while you are actively shaping the question.

The handoff moment usually arrives after one of these:

- a **plan** has become clear enough to execute;
- a **prototype** answered its question and now needs production rigor;
- a **diagnosis** established a falsifiable cause;
- a **partial implementation** needs independent completion, tests or reviewed delivery.

Hand off when the next step deserves a durable owner, not merely another chat turn.

## Hand off the outcome, not the transcript

Suppose your local Agent reproduces a checkout defect and finds that one update route trusts
client-only validation. Do not ask First Mate to “continue this chat.” Package what another
accountable Agent needs:

```text
Desired outcome
Stop checkout address changes from bypassing server validation.

Current evidence
Reproduced on main. The update route accepts payloads rejected by the create route.

Durable artifacts
Issue 214 and diagnosis commit abc123 on branch diagnosis/address-validation.

Constraints
Preserve the public API and existing checkout payloads.

Authority boundary
Open a pull request through the repository's checks. Do not merge.
```

The transcript may remain useful background, but the handoff stands on an outcome, inspectable
evidence and explicit boundaries. If code matters, commit it to a branch, produce a patch or point
to another durable artifact. An uncommitted local working tree cannot carry the responsibility.

## Let First Mate accept responsibility

Give the package to First Mate through the interface your Fleet actually provides. A connected
local Agent may use an approved integration to preserve the same package as an external event when
First Mate is already working. AgentOS does not invent one universal handoff command.

Preservation is not acceptance. An external event records evidence for later reconciliation; it
does not automatically create work. First Mate first checks current projects, Tasks, ownership and
authority. Accepted execution begins when AgentOS records a Task and one active accountable
Assignment.

That boundary prevents a useful local idea from silently becoming duplicate work or exceeding the
authority you meant to grant.

## Take the evidence back

The Fleet can return a diagnosis report, a reviewed pull request, a blocker or one exact decision.
Review that result locally if that is where you work best. You can ask your local Agent to compare
the evidence, refine the direction or prototype the next question, then send another bounded
handoff.

```text
local exploration
  → bounded handoff
  → accountable Fleet work
  → evidence back
  → review or refine locally
```

Each loop starts from current durable evidence. It does not assume an earlier transcript still
describes the company.

## Beyond coding agents

The same handoff can begin in an employee workplace that has already assembled the person's
relevant decisions and context. A built-in Agent can help revise a draft or ask First Mate, while
the human explicitly approves what enters the company. Read
[Human work surfaces](/docs/concepts/human-work-surfaces) for that wider interface pattern and
[Continue local work with the Fleet](/docs/operate/continue-local-work) for the reusable handoff
checklist.
