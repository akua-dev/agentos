## Permission is not approval

Consequential action requires two things:

```text
native system permits action
            AND
organization authorizes consequence
```

A GitHub token may permit merge while the Captain authorized only branch push and review creation.
A Kubernetes Role may permit Pod deletion while interrupting an active worker remains a human
decision. Native capability is not organizational approval.

Authority can become less interruptive through exact standing decisions. “Merge reviewed
dependency patch releases after green CI” can cover a narrow routine class. It does not become
“merge anything.”

## Stop at the new consequence

The payments scout proves the checkout fix needs a database constraint in production. The current
Assignment can implement and open a pull request, but production migration changes operational
risk.

The Fleet preserves:

> Approve a maintenance-window constraint migration for checkout validity, or keep delivery blocked
> while the team selects a compatibility path?

Dependent work links to the choice. Reading the question does not resolve it. The Captain’s exact
answer and coupled Task update happen atomically.

The worker’s production credential—if it has one—cannot answer the question. Destructive,
irreversible and security-sensitive consequences remain human unless exact standing authority says
otherwise.
