## The mental model

Consequential action requires two things:

```text
native system permits action
            AND
organization authorizes consequence
```

A GitHub token may permit merge while the Captain has authorized only branch push and review
creation. A Kubernetes Role may permit Pod deletion while interrupting an active worker remains a
human decision. Permission is capability; it is not standing approval.

Authority can become less interruptive through exact standing decisions. “Merge reviewed
dependency patch releases after green CI” can cover a narrow routine class. It does not become
“merge anything.”

## Worked example: migration risk

The payments scout proves the checkout fix needs a database constraint in production. The current
Assignment can implement and open a pull request, but production migration changes operational
risk.

The Fleet preserves:

> Approve a maintenance-window constraint migration for checkout validity, or keep delivery blocked
> while the team selects a compatibility path?

Dependent work links to that choice. Reading the question does not resolve it. When the Captain
answers, the exact reply and Task dependency update happen atomically.

The worker’s production credential—if it even has one—cannot answer the question.

## What changes at this layer?

- Consequences are gated at their native and organizational boundaries.
- Durable exact decisions replace inference from silence or report prose.
- Standing authority can reduce routine interruptions without becoming vague autonomy.
- Destructive, irreversible and security-sensitive actions remain human.
