## The mental model

AgentOS uses a crew hierarchy:

```text
Captain → First Mate → Second Mate → Crewmate
```

Captain is the human role and may be held by a person or team. First Mate is the regular company
interface. A Second Mate owns one persistent domain. A Crewmate owns one bounded ship or scout
Assignment.

Each Agent reports through one direct supervision edge. Parents form and supervise their own
subtree; ancestors do not reach around them for routine work. Humans should not need to know which
internal Second Mate to tag—the company routes intent.

## Worked example: route the checkout Task

The Fleet already has a Second Mate chartered for payments reliability. First Mate routes the
accepted Task to that domain. The Second Mate creates a scout Crewmate for diagnosis, evaluates the
report and later creates a ship Crewmate for delivery.

The checkout worker does not open a competing Captain conversation. It reports the migration risk
to the Second Mate, which sends the material decision upward. First Mate presents the consequence
in ordinary company language.

If no durable domain exists, First Mate can create a bounded Crewmate directly. A Second Mate is
not mandatory ceremony for every Task.

## What changes at this layer?

- Ownership gains an accountable supervision path.
- Domain context can persist without making one root Agent do every job.
- Reports and escalations move upward; outcomes move downward.
- Human communication can stay company-facing while internal routing changes.
