## The mental model

Long-lived organization cannot depend on one process remaining alive. Agent identity, accepted
work, home state and delivered evidence have different persistence mechanisms:

```text
Agent + Assignment → PostgreSQL
home + worktree + memory → PVC
live workload → Kubernetes
native session → Herdr
landed delivery → Git
```

Pod loss is not work loss. It is a condition that supervision reconciles across those authorities.

## Worked example: the worker disappears

The checkout worker has a commit-in-progress and failing compatibility test when its Pod is
controlledly replaced. The home PVC remains.

Recovery does not create a new Agent and second active Assignment. It verifies the intended Agent
identity, reuses the same home, restores the reviewed runtime shape, finds the worktree and resumes
the native harness. The worker reads current Git and test state before continuing.

A truthful recovery report names:

- time to detect the loss;
- time to useful work;
- whether changes survived;
- whether effects duplicated;
- any human repair.

A green Pod alone proves none of these.

## What changes at this layer?

- Runtime processes become replaceable without discarding organizational identity.
- Unfinished work can continue instead of restarting from a summary.
- Recovery has observable acceptance criteria.
- The company can remain accountable across ordinary infrastructure failure.
