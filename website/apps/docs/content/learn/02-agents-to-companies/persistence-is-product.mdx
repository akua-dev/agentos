## Processes are replaceable

Long-lived organization cannot depend on one process remaining alive. Agent identity, accepted
work, home state and delivered evidence have different persistence mechanisms:

```text
Agent + Assignment → PostgreSQL
home + worktree + memory → PVC
live workload → Kubernetes
native session → Herdr
landed delivery → Git
```

Pod loss is not work loss. It is a condition supervision reconciles across those authorities.

## Recover the same worker

The checkout worker has a commit-in-progress and failing compatibility test when its Pod is
replaced. Its home PVC remains.

Recovery does not create a new Agent or second Assignment. It verifies identity, reuses the home,
restores the reviewed runtime, finds the worktree and resumes the native harness. The worker reads
current Git and test state before continuing.

A truthful recovery report names:

- time to detect the loss;
- time to useful work;
- whether changes survived;
- whether effects duplicated;
- any human repair.

A green Pod alone proves none of these.
