## The mental model

Steering corrects an active outcome without discarding ownership or creating a duplicate worker.
It is useful when new evidence invalidates the current next action and waiting for a full report
would waste effort.

A supervisor sends one concise correction through the released durable hierarchy path. When a
direct terminal path is the only safe way to reach a currently moving native session, it uses a
doorbell or direct human intervention carefully and reconciles the result.

Steering is not interruption by default. The goal is to change the smallest stale assumption.

## Worked example: stop an obsolete migration

The onboarding worker begins designing a new database column. A recently merged provider change
shows the project now exposes the needed field through an existing endpoint.

First Mate or the owning Second Mate sends:

> New evidence: provider change 842 exposes `valid_until` through the current endpoint. Re-evaluate
> the proposed migration before changing schema; preserve current work and report whether the
> existing API satisfies the outcome.

The same Assignment continues. The worker reads current Git/provider state and adjusts. No new
Agent is launched to race the old one.

If the Captain speaks directly in the attached terminal, that instruction wins over stale brief
assumptions and is recorded durably afterward.

## What changes at this layer?

- New evidence can alter work before a full cycle completes.
- Correction targets one owned session instead of broadcasting.
- Durable ownership and history remain intact.
- Steering provenance is distinguished from automated wakes.
