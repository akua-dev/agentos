The Fleet AI Gateway is optional pooled capacity for reviewed Codex subscription accounts with an
explicit OpenAI API-key fallback. Direct per-Agent authentication remains a complete AgentOS
topology.

Use the owning procedure before selecting, installing, authenticating, recovering, rotating or
retiring the gateway. It keeps server-owned provider OAuth and quota-aware routing inside a
deliberate service boundary. Client Agents receive only the scoped connection material intended
for them.

Clients may live in `agentos` or a labeled Second-Mate domain namespace. They call
`ai-gateway.agentos.svc.cluster.local`; the Gateway NetworkPolicy requires both the Fleet Namespace
label and the client Pod label. Kubernetes Secret references remain namespace-local, so First Mate
places the approved client token in each selected domain and treats it as visible to that domain’s
Second Mate. Provider OAuth and the Gateway vault never leave the core namespace.

## What it does not own

The gateway does not create Agent identity, Assignments, human authority or provider-neutral model
semantics. It is not a universal LLM abstraction and does not make one account’s quota an
organizational permission.

Inspect accounts, health, routing state and observed provider failures through the service’s
current interfaces. A `401` and a `429` have different causes; recovery does not silently swap
identities or introduce an API-key fallback that was never approved.

Because the feature is optional, every core Docs path remains understandable without it.
